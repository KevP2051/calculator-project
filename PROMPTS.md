# AI Development Prompts

## Prompt 001 — Project Constitution

### Prompt

Project context:
- Full-stack calculator application.
- Go backend exposing a stateless REST API.
- Expected development time: approximately 2–4 hours
- This constitution applies specifically to the Go backend of the calculator application.
-The backend is responsible for exposing the calculator functionality through a REST API. Frontend concerns are outside the scope of this constitution.
-The backend is expected to be developed in approximately 2 hours

The constitution should establish the following principles:
- API-First: The backend should have a clearly defined API contract and must remain independent from frontend/UI concerns.
- Layered Architecture: Maintain clear separation of responsibilities between the API/infrastructure, application/service, and core calculator logic. The architecture must remain proportional to the simplicity of the calculator.
- Testability: Core calculator behavior and important API success/error paths must be covered by automated tests.
- Simplicity and Idiomatic Go : Prefer readable, maintainable, idiomatic Go and the standard library.
- Avoid Overengineering: The solution must remain proportional to the project's scope and complexity. Avoid unnecessary abstractions, patterns, layers, dependencies, and infrastructure.
- Incremental Development: Development must proceed one task at a time according to the tasks generated by the SDD workflow. After completing a task, the AI agent must stop and wait for developer review and testing before continuing.
- AI agents must never create commits, push changes, merge branches, or rewrite Git history. The developer reviews, tests, commits, and pushes changes manually.

The constitution should prioritize correctness, maintainability, and
testability over optional features.

The architecture should remain proportional to the project's scope.
The developer has final authority over technical decisions.
AI-generated code must be reviewed before being committed.

Keep the constitution concise and avoid implementation-specific decisions
such as API endpoints, data types, HTTP status codes, numerical limits,
or folder structures. Those decisions should be made later during
Specify, Clarify, and Plan.
